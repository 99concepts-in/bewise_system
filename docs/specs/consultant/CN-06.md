# CN-06 Live session (incl. CN-07 troubling sheet) — screen spec

> **Owner:** CONSULTANT · Route `/consult/appointments/[id]/session` · Milestone K4 · Boards: `design/consultant-v2/CN-phone-02-…` (right), `CN-phone-03-troubling-end-session-blend.jpg`, iPad `CN-board-04/05`

## Purpose
Be present with the client; capture what matters with as few taps as possible; never lose a word.

## Layout (phone)
1. Top bar: back (confirm if unsaved queue) · client name · **timer** (elapsed since Start, turns gold at scheduled end, never red) · online: "Open video" button (meeting_url).
2. Three tabs: **Notes 🔒 · Troubling · Summary** (Summary tab label "Summary (optional)").
   - **Notes 🔒**: large textarea, lock icon + "Only you can see this". Mic button (dictation). Autosave indicator "Saved · 11:24" / "Saving…" / "Offline — saved on this device".
   - **Troubling**: "What's troubling her?" chip grid, pre-selected chips from intake tagged "from intake" (dotted outline) and last session ("last time"); tap toggles; "More" opens **CN-07** full sheet grouped *Fear & worry · Heart · Self · Energy · Temper* with search and "Add new" (edits `concern_catalog`, D-27). Optional intensity long-press (mild/moderate/strong) — v1.1.
   - **Summary (optional)**: textarea for a client-shareable summary + "Share with client" toggle (off by default, D-26). Helper: "Written for her — kind, simple, no private notes."
3. Sticky footer: **End session** (outline) · **Build remedy** (navy → CN-09 with this appointment).

Pronouns: copy uses the client's chosen pronoun from CRM if present, else "they" ("What's troubling them?") — boards say "her" for illustration only.

## Behaviour
- Entering the screen calls `startSession(appointmentId)` once (idempotent) → status `in_session`, history `started`, creates `consultation_records` row.
- **Autosave**: debounce 1.5 s after typing + on tab switch + on `visibilitychange`; `savePractitionerNote({ recordId, body, clientRev })` with optimistic concurrency (`row_version`); conflict (other device) → keep both, show "Edited on another device — merged below".
- **Offline** (CN-27): edits queue in an **encrypted outbox** (IndexedDB, AES-GCM with a non-extractable WebCrypto key per session, purged after successful sync and on sign-out). The service worker never caches note API responses. ⚠️ This needs HUB sign-off against Master Plan "never cache notes" — default: outbox ON, cleared on sync (see log).
- **Dictation**: Web Speech API (`SpeechRecognition` / `webkitSpeechRecognition`, lang `en-IN`, switch `hi-IN`) — on-device/browser service; we never upload audio. Unsupported → hint "Use your keyboard's mic". Interim text shown grey, final text appended at cursor.
- **Troubling**: each toggle calls `setSessionConcerns({ appointmentId, concernKeys })` (debounced 800 ms) — idempotent full set.
- End session → CN-08 sheet (Completed / No-show · follow-up in 2/3/4/6 weeks / none · Share summary toggle · Give remedy / Done) → `endSession(...)` emits `appointment.completed`, `client_summary.shared` if toggled, schedules `follow_ups`.

## Data & permissions
`practitioner_notes` 🔒 author-only RLS (no owner/manager access — D-03); `client_summaries` client-visible only when `shared_at` set; `session_concerns` consultant + aggregate analytics only. All functions `requirePermission('consultation.session.edit')` + `appointment.consultant_id = me`.

## States
Loading (skeleton tabs) · appointment not today → banner "Scheduled for 21 Nov — start anyway?" · already completed → read-only (opens CN-14) · no-show recorded → read-only · error saving → persistent amber bar "Not saved — retrying" (never a success toast while unsaved).

## Accessibility
Tabs are a proper tablist; timer `aria-live="off"` (announced on demand); mic button has pressed state and announces "Listening"; chips are toggle buttons with `aria-pressed`.

## Acceptance
- Typing then killing the network then closing the tab and reopening online → text present on server.
- Concern chips from intake appear pre-selected and tagged; deselecting persists.
- A manager JWT calling the notes API gets 0 rows; owner too.
- Summary is never visible to the client unless "Share with client" is on at End session.

# CN-03 Today — screen spec

> **Owner:** CONSULTANT · Route `/consult` (phone home) · Milestone K2 · Boards: v4 `design/consultant-v4/CN4-board-00-today-prep-feelings.jpg` (left), layout `design/consultant-v2/CN-phone-01-signin-applock-today.jpg`, iPad `CN-board-00-today-ipad-phone.jpg`

## Purpose
His first screen every day: who's next, what's coming, what needs him. One calm column, one primary action (Start / Prepare).

## Layout (phone 375–430 px, v4 Soft Bloom)
1. **Header**: real photo avatar (`design/assets/people/jitu-bhaiya-square.jpg` until profile upload) · "BeWise / CONSULTANT" · bell (→ CN-04, dot when unread) .
2. **Greeting** two-tone: "Good morning Jitu" (navy) + "you have *n* sessions today" (grey). Morning < 12:00, afternoon < 17:00, evening otherwise (IST). n = confirmed/checked_in/in_session today.
3. **Priority card** (only if any unacknowledged safety flag — CN-36): rose card "A client needs a gentle check-in" → opens that client's prep. Never shows the answer on Today, just the client name.
4. **Next session hero** (white card, 32 px radius): "Next session · in 18 min" (or "· now", "· at 3:00 PM"), client photo/initials, name, type · time · mode icon + label, booking note quote (CL-15, max 2 lines, "…more"), mood character of her latest journal entry (if shared, D-15). Buttons: **Prepare** (outline → CN-05) · **Start** (navy → CN-06). Start enabled from 15 min before start; earlier it reads "Prepare" only. Online: Start also opens the meeting link in a new tab (setting).
5. **Tiles** (3): follow-ups due (→ CN-20) · new client notes & feedback since last visit (→ CN-21) · remedies being prepared (→ CN-10 tracker list). Tile hidden if its feature flag is off; `0` shows as "none" in grey.
6. **Today's timeline**: remaining sessions (time, name, type chip, mode icon, intake status dot: "intake ✓ / not filled"), pending holds dashed "Awaiting payment", external busy "Busy (Google)" in grey. Tap → CN-05.
7. Bottom floating nav: Today · Clients · (+) · Calendar · Me. (+) sheet: Book for a client (CN-15) · Quick note (client picker → private note) · Give remedy (client picker → CN-09).

iPad/laptop: left rail; hero + timeline left column, tiles + notifications preview right column.

## Data
| Element | Source |
|---|---|
| Sessions today | `scheduling.listAppointments({ consultantId: me, from: todayIST, to: todayIST, status: active })` |
| Booking note | `appointments.client_note` (consultant-only) |
| Latest feeling | `journal` read API (CLIENT; respects sharing toggle) — `@cross(CLIENT)`; hidden if unavailable |
| Safety | `intake_flags` active `safety` unacknowledged for my clients |
| Tiles | `listFollowUps({ due: true })` count · `listSessionFeedback({ since: lastSeenAt })` count · remedy orders not delivered count |
Server component; one `getTodayView()` aggregate function in `consultation` (internal) to keep it to one round trip. Revalidate on focus and every 60 s while open.

## States
- **Loading**: skeleton greeting + hero + 3 tiles.
- **Quiet day** (no sessions): CN-27 — owl mascot, "A quiet day — no sessions booked", buttons "Open availability" · "Follow-ups due (n)".
- **All done**: hero becomes "That's everyone for today" + count completed; remedies to give for completed sessions without a remedy ("2 sessions need a remedy" → CN-09).
- **Error**: inline card "Couldn't load today" + Retry; nav still works.
- **Offline**: last loaded Today (non-sensitive fields only: names, times) from memory with "Offline — showing 9:12 AM" pill; Start/Prepare disabled with reason. No booking notes or flags cached offline.
- **No permission** (non-consultant): redirect to their own space.

## Events / actions
None emitted by viewing. Start → `startSession(appointmentId)` (K4) → `in_session` (history `started`).

## Accessibility
Hero is a landmark with heading; "in 18 min" has an `aria-live="polite"` update each minute; tiles are buttons with full labels ("4 follow-ups due"); mood character has alt text with the emotion name; 44 px targets.

## Acceptance
- With 5 sessions today, the hero shows the next upcoming (or the in-progress one), timeline shows the rest in time order.
- A safety flag on any client today shows the priority card; acknowledging it on CN-36 removes it.
- Manager/owner accounts cannot reach `/consult` (403 page) and the API returns no booking notes.

# CN-05 Session prep (incl. CN-33 case summary, CN-36 safety & "since last time") — screen spec

> **Owner:** CONSULTANT · Route `/consult/appointments/[id]/prep` · Milestones K3 (case summary/flags), K4 (prep), K6 (AI) · Boards: v4 `CN4-board-00` (middle), `design/consultant-v2/CN-phone-02-notifications-prep-live-session.jpg`, `design/intake-v2/IN-board-06…`, `IN-board-07…`

## Purpose
"Before you meet Priya" — everything he needs in 30 seconds, then **Start session**.

## Layout (phone, top → bottom; one scroll)
1. Header: back · avatar · bell. Title two-tone "Before you meet" / "*Priya*". Sub: type · time · mode · "Session 3" · Intake status.
2. **Safety banner** (rose, only if active `safety` flag): "Safety: answered *Sometimes* on 14 Nov — support shown." + **Call** · **WhatsApp** · **Mark as reached out**. Acknowledged → banner turns soft grey "You reached out on 14 Nov". Never collapsible while unacknowledged.
3. **Case summary** card (first consultation) / **Since last time** card (follow-up) — title + tag "AI · verify with client".
   - 4 lines (first) or 3-line progress note (follow-up) from `getCaseSummary`.
   - States: generating ("Preparing a summary…" shimmer, poll every 5 s up to 60 s) · `no_consent` ("She chose not to have an AI summary — see her answers") · `failed/rejected` ("Summary unavailable — see her answers") · no intake ("Intake not filled yet" + "Send reminder" → WhatsApp deep link).
   - Footer link **Her answers** → CN-34 (tabs Summary · Answers · Changes).
4. **Flags** chips (from `intake_flags`; label from decrypted answers, max 24 chars): Alcohol-free · Allergy: lavender · Medicine: thyroid · Pregnant · Under 18 · Under a doctor's care. Tap → the answer in CN-34.
5. **Progress since last remedy** (consultant audience, `getProgressSummary`) — 3 lines, "Auto summary"; insufficient data text when applicable. Follow-ups only.
6. **Her note** (booking note CL-15), quoted.
7. **Recent feelings**: 7-day row of mood characters (if journal shared) → "See all" CN-13 Feelings tab.
8. **Troubling last time**: chips from previous session's `session_concerns`.
9. **Current blend**: flower names, dosage, given on date, delivery status (from remedies) → CN-14 past session.
10. **Questions to explore** (3, AI, collapsed by default) — first consultation only.
11. **Flowers to consider** (CN-35) — collapsed row "Flowers to consider (6) · reference only" → sheet with list, reasons, "+ Add to blend" (adds to the draft formula for this appointment; opens CN-09 on demand). Never rendered for any other role.
12. Sticky bottom: **Start session** (navy pill) → CN-06. Disabled > 60 min before start with hint; enabled anytime for the consultant if he confirms "Start early?".

## Data
`getAppointment` · `getCaseSummary(appointmentId)` · `intake_flags` (+ labels via `getIntakeAnswers` partial) · `getProgressSummary({clientId, audience:'consultant'})` · `listSessionConcerns(prevAppointmentId)` · `getCurrentRemedyForClient` (consultant view) · journal week (CLIENT API, sharing respected) · `getFlowersToConsider` (lazy, on expand).
Opening prep writes `audit_logs view_sensitive` once per appointment per day and enqueues progress refresh if older than 6 h.

## States
Loading skeleton per card (cards load independently; summary may arrive later) · error per card with retry · offline: whole screen unavailable ("Prep needs a connection — it contains private information") · cancelled/expired appointment → read-only banner.

## Privacy
Nothing on this screen is cached by the service worker; no flag text or summary in notifications. QA note for designers: the v4 board's line "Responding well to the current blend" is **not allowed** AI output (efficacy claim) — real summaries only report what the client said.

## Acceptance
- First consultation with AI consent → 4-line summary + 3 questions + flags + flowers to consider.
- Follow-up with check-in → "Since last time" 3 lines + progress summary + last troubling chips + current blend.
- Safety "often" → banner on top; Today priority card; acknowledging updates both.
- Manager hitting the route → 403; `getCaseSummary` as manager → `FORBIDDEN`.

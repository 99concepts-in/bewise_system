## Purpose
A remedy in under a minute: pick flowers, check dosage, **Give remedy**.

## Layout (phone)
1. Header: back · "Her blend" · client name · source chip ("After session 21 Nov" or "Reorder").
2. **Quick start row**: **Duplicate last** (copies last given formula) · **Template** (CN-11 picker) · **Flowers to consider (n)** (sheet, reference only — appointment context with intake).
3. **Blend list** (each row): flower name (+ group colour dot) · drops stepper (default **2**, Rescue **4**) · 🔒 "Why" (private reason, one line, optional) · remove. Drag to reorder. Counter "5 flowers". Soft warning at > 7: "Most blends use up to 7 — keep going?" (not blocking).
4. **Add flower** button → bottom sheet: search, groups (Bach's 7 groups), Recently used, hidden flowers excluded (link "Show hidden"). Already-added flowers show ✓.
5. **Dosage** card (client-facing): drops per dose (default **4**), times per day (default **4**), weeks (default **3**), bottle **30 ml** (10/20/30), base: **Brandy** / **Alcohol-free** (default from intake `alcohol_free` flag, with tag "from intake"; switching away from alcohol-free when flagged asks to confirm). Instructions text (prefilled template, editable, client-facing, 300 chars).
6. **Price line**: "Included in today's consultation — ₹0" when linked to a paid session without a remedy yet; else "Reorder · ₹{remedy.reorder_price}" (from settings; if not set → "Price not set — ask the owner" and Give remedy disabled for reorders). `// @decision(D-02)`
7. Sticky footer: **Give remedy** (navy). Secondary "Save as template".

Draft autosaves silently (`formulas.status = 'draft'`, debounce 1 s); no draft/approve UI (D-25).

## Give remedy flow
Tap → confirm sheet: blend summary (names + drops), dosage line, bottle/base, "Goes to Priya and to the office now", price line → **Give remedy**.
`giveRemedy({ formulaId, idempotencyKey })` server, one transaction:
1. Validate: ≥ 1 flower, drops 1–10, times/day 1–8, weeks 1–12, bottle ∈ {10,20,30}, base set, every flower active in library.
2. Create immutable `formula_versions` (vN) + `formula_items` (reason 🔒 column, author-only RLS).
3. `formulas.status = 'given'`; previous given formula for this client → `superseded`.
4. `remedy_orders` row: `{ formulaVersionId, clientId, appointmentId?, bottleSizeMl, base, pricePaise (0 or reorder price), includedInAppointmentId? }`. One included (₹0) remedy per paid appointment — second one is priced as reorder (with a notice).
5. Emit `remedy.given { formulaVersionId, remedyOrderId, clientId, bottleSizeMl, pricePaise, includedInAppointmentId? }` (last two **additive** fields) → commerce creates the remedy sales order; notifications tells the client; fulfilment prep uses `getPrepSheet()` (names, drops, bottle, base, label text, **ALCOHOL-FREE BASE** banner) — no reasons, no notes.
6. Idempotency key (client-generated UUID) → double tap returns the same result.

→ **CN-10 Remedy given**: success illustration (mascot once), "Sent to Priya · The office is preparing it", tracker (Given ✓ → Preparing → Dispatched → Delivered from fulfilment stages), buttons "Back to Today" · "Save as template".

## Data / permissions
`remedies.formula.edit` + client assigned; reasons readable only by author (`formula_items.reason` column RLS + excluded from `v_prep_sheet` and `getCurrentRemedyForClient`). Library from `bach_remedies` (38 + Rescue Remedy seeded, `hidden` per consultant, descriptions pending D-10).

## States
Loading · empty blend ("Add a flower, duplicate her last blend, or start from a template") · offline: building allowed (draft kept in memory + encrypted outbox), **Give remedy disabled** ("Needs a connection") · error on give → nothing sent, clear message, retry keeps idempotency key · remedy orders flag off (`remedy_orders`) → Give remedy creates the formula and remedy order but shows "Office hand-off not live yet" until MANAGER M2 is live.

## Acceptance
- Duplicate last → identical flowers/drops/dosage, new draft; Give → v(n+1), old version superseded.
- After a paid session, Give → `pricePaise = 0`; second Give for the same appointment → reorder price with notice.
- Client's My Remedies (CLIENT) shows names + instructions, never reasons; manager prep sheet shows names/drops/bottle/base, never reasons.
- Alcohol-free intake flag → base preselected alcohol-free and prep sheet shows ALCOHOL-FREE BASE.
- Double tap → one remedy order, one event.
